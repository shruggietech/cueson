# S026 research: scripted target construction and dialect conversion

## Authority and inspected implementation

This research applies GitHub #61, the S026 specification, the ratified constitution, and the architecture of record. Inspected implementation includes `internal/convert/project.go`, `internal/convert/render.go`, `internal/convert/markup.go`, `internal/model/scripted.go`, `internal/model/scripted_capture.go`, `internal/model/scripted_text.go`, `internal/model/scripted_native.go`, and `internal/codec/scripted/parse.go` and `render.go`. No production implementation was changed during research.

## Decision: preserve the public source validation boundary

Normal `Document.Validate` delegates current scripted documents to `validateScriptedDocument`, which unconditionally calls `scriptedSourcePrivacy(source, document.Format)`. That source validator requires the original primary asset to declare the same `ScriptType` and style-section dialect as the document. Consequently an otherwise valid private target preserving an original SubRip/WebVTT source envelope or the opposite scripted dialect cannot use ordinary public document validation. The current scripted renderer invokes that same validation. Updating the private schema identity alone does not solve this conflict.

Do not relax `Document.Validate`, replace the immutable envelope with generated target bytes, fabricate a source asset, or allow a Cue JSON flag to bypass source validation. Add an explicit internal constructed-target path, with no schema or JSON property exposing the distinction. Conversion validates the original complete document and source integrity before analysis and target construction. The constructed target keeps exactly the original source envelope, source producer identity, and current development scripted identity; it is never published as Cue JSON.

Recommended narrow model API is `ValidateScriptedTarget(source, target Document) error`, used only by the internal codec's constructed-target renderer. Validate the original source normally and require exact equality of the immutable source envelope. Extract the existing scripted validation implementation behind a private validation mode. The constructed mode changes only original-source grammar checking, while retaining collection bounds, asset structure, ownership, contiguous physical order, dialect shape, native scalar/privacy rules, declaration framing, style resolution, event-to-cue linkage, projections, summaries, diagnostic safety, and independently checked retained captures. Capture-free target construction must not interpret UTF-16 or other supported text-source bytes as scripted physical lines; original integrity is still verified by the source package. If retained captures exist in a dialect conversion, inspect the original bounded physical captures and keep their source order unchanged.

Recommended codec API is `RenderTarget(ctx context.Context, source, target model.Document) (RenderResult, error)`. Share a private serialization function with existing `Render`; keep existing `Render` public behavior unchanged. The new entry point invokes constructed validation and full source integrity validation, then uses the same bounded owner serialization and complete target reparsing. No target bytes escape on invalid context, cancellation, malformed records, malformed attachment data, native precision/framing errors, privacy rejection, output bounds, or parser rejection. Conversion strictness is enforced against the complete loss report before invoking the renderer. Retained harmless diagnosed source records may require permissive native rendering even when the conversion itself has no loss; generated targets must introduce no unaccounted diagnosed content.

## Decision: deterministic text-source target defaults

Construct text-source targets with ordered `Script Info`, the matching style section, and `Events`. Use current development schema URI/version, experimental ingest/render/restore capabilities, the original producer, a cloned unchanged source envelope, empty common metadata after its accounted omissions, non-null native collections, no captured headers/recognized raw lines/timestamps, and no original-source declaration references. Use one canonical `Default` style, canonical field names from `model.ScriptedCanonicalFields`, and one editable native dialogue owner per retained cue. Explicit canonical declarations may be emitted or inserted by the existing constructed-owner renderer. Target IDs and physical orders are deterministic and unrelated to input file paths.

Suggested documented defaults match existing native baseline fixtures: Arial, size 20, opaque white primary, red secondary, black outline/shadow, no bold/italic/underline/strikeout, scales 100, spacing/angle 0, border style 1, outline 2, shadow 0, bottom-center alignment 2, margins 10, encoding 1, and SSA AlphaLevel 0. Script metadata needs matching ScriptType and WrapStyle 0; optional play-resolution defaults may be added only as explicitly documented target defaults, never inferred video observations. Source formats lacking a style do not lose an observed font or resolution when these defaults are constructed. Preserve supported inline emphasis through event overrides rather than inventing source-native style provenance.

Compute `ProjectScriptedText` facts from the final encoded event text and quantized timing. Copy derived lines, plain text, spans, tags, karaoke, and token facts consistently into the private native/common owners. A dialogue cue's projection uses the existing internal `native_derived` linkage because it derives from the constructed target owner; the private representation is not a new observation of original source-native data. Empty actor fields require empty speakers and no speaker-field provenance. Recompute summaries safely for zero cues rather than indexing cue zero.

## Decision: checked nearest-centisecond quantization

Use deterministic nearest-centisecond rounding with ties upward for nonnegative milliseconds. Compute quotient and remainder before incrementing; never evaluate an unchecked `milliseconds + 5`. Report one timing-degradation loss for each changed start or end endpoint with a portable `/cues/N/timing/...` path and fixed endpoint context. Strict conversion rejects those losses before rendering. Recompute duration from rounded endpoints. Reject a rounded interval with end not greater than start, negative timing, and overflow beyond the largest representable multiple of ten. Do not enlarge collapsed intervals automatically because that adds an independently invented timing policy. Native scripted source timestamps are exact centiseconds, but valid editable Cue JSON may change common cue timing independently; all scripted targets therefore apply this same policy to common timing, including dialect conversion. Recompute target karaoke/token facts using quantized common timing and reject any newly unsupported karaoke interval.

## Decision: literal text must not become controls

The repository scanner recognizes `\\N`, `\\n`, and `\\h` outside override groups; it does not implement a standard lossless brace escape or a general doubled-backslash escape. Convert actual line feeds to `\\N` and nonbreaking spaces to `\\h`. Preserve ordinary literal backslashes only when they do not introduce a recognized control pair. Reject literal opening/closing braces and literal backslash-N, backslash-n, or backslash-h sequences rather than silently acquiring override, line-break, or nonbreaking-space semantics. The complete reparsed target must have the expected plain text. Literal braces or control-looking text are documented fatal edges in otherwise supported conversion directions. Do not invent empty-override separator tricks as a portability claim.

Translate paired shared emphasis tokens into explicit `\\b1`/`\\b0`, `\\i1`/`\\i0`, and `\\u1`/`\\u0` event overrides, tracking nested state so closing a nested same-kind span restores the preceding state. Reuse established source markup tokenization and issue accounting for unsupported fonts, WebVTT voice/class/ruby/language/inline timing, entities, NUL handling, and malformed markup, without treating synthetic empty-line placeholders as original observed emphasis. An empty source payload line is representable by adjacent native explicit breaks and should not receive a text-target-only blank-line degradation loss.

## Decision: preserve variants without assuming lexical equivalence

Dialect conversion should deep-copy target-owned editable structures, retain physical order and unchanged native records, update ScriptType and the style-section name, map target declaration identities, and remove capture fields only from changed recognized headers/records/owners. Unchanged comment/blank/unknown/attachment records retain original captured raw content at their original source order; attachment names/ranges remain bounded and private. Do not mutate original native slices, pointer unions, source assets, or captured timestamps. Invalid preservation-only styles/events/attachments remain fatal rather than disappearing during projection.

Exact SSA-to-ASS style alignment mapping is `1->1`, `2->2`, `3->3`, `5->7`, `6->8`, `7->9`, `9->4`, `10->5`, `11->6`; reverse these pairs for ASS-to-SSA. Values outside the ratified portable mapping are explicit fatal or accounted unsupported edges. Event alignment override tags are a separate dialect-independent representation and must not be blindly renamed. Common font, font size, bold/italic, margins, encoding, border/outline/shadow scalars, actor/style references, event type, timing, text, safe effects, and representable override text can retain their target-owned values. Source-only columns or controls require atomic omission/degradation entries, including observations omitted even when a scalar is a neutral default; target-only neutral defaults are construction rather than lost observations. A canonical ASS style consequently need not be a loss-free SSA conversion merely because dialogue text and timing survive.

ASS Layer and SSA Marked have different roles, so replacing one with a target zero default must account for the source observation; it is not a semantic identity mapping. Likewise color/alpha conversion requires an explicit policy rather than simple column renaming. The maintained libass implementation uses SSA BackColour for both outline and shadow, ignores SSA TertiaryColour in rendering, applies AlphaLevel to primary/secondary/outline alpha, and fixes shadow alpha to 128. ASS supplies separate per-color alpha and outline/back colors. Preserve safe lexical values where useful, but report actual presentation degradation whenever those differing roles cannot be retained. Do not claim that ASS OutlineColour renamed to SSA TertiaryColour preserves rendered outline color. Unsupported style-scale/spacing/angle/underline/strikeout columns can be reported individually or represented through explicitly supported event overrides; the chosen policy must agree with loss fixtures and documentation.

Post-implementation independent review identified additional observations requiring explicit accounting. Independently supplied common metadata, OCR, placement, and cue identifiers have no native variant output representation; report and clear them only in the private target, preserving native actor and karaoke observations that do survive. The generic cue identifier omission uses `conversion_source_identifier_omitted`. SSA per-color nonzero high-byte alpha values are retained native observations even when the renderer uses AlphaLevel or fixed shadow alpha instead. If mapping overwrites such a nonzero observation, report a field degradation; zero inactive alpha remains ordinary representation normalization, and an identical nonzero alpha that survives in the target is not reported lost. This conservative distinction accounts for preserved source-native information without claiming pixel equivalence.

## Proposed conversion implementation APIs and ownership

The target-projection agent owns new `internal/convert/scripted_project.go`, `scripted_variant.go`, focused tests, and the narrow model/codec constructed-target validation extraction. Root owns router changes in existing project/render/conversion files and the report vocabulary. Settled helpers are `projectScriptedTarget(ctx context.Context, source model.Document, targetFormat string, translations []payloadTranslation) (model.Document, []Loss, error)`, `projectScriptedVariant(ctx context.Context, source model.Document, targetFormat string) (model.Document, []Loss, error)`, `quantizeScriptedTiming(timing model.Timing) (model.Timing, error)`, and `encodeScriptedLiteral(text string) (string, error)`. The projection helpers perform analysis-time construction without rendering and return complete bounded timing/variant losses before the strict gate. Timing uses `conversion_scripted_centisecond_quantized`; omitted and weakened variant fields use `conversion_scripted_variant_field_omitted` and `conversion_scripted_variant_field_degraded`, respectively. Passing context through projection makes cancellation observable inside large native-copy loops.

## Focused verification

- Four text-to-scripted baseline goldens reparse to expected timing, plain text, supported emphasis, default style, native linkage, and experimental identity.
- Repeated conversions produce byte-identical output and reports; original document JSON and source restoration remain unchanged after each conversion.
- Historical v1.0.0 text documents produce private current scripted targets without changing the original schema, producer, or envelope; current public validation still rejects mismatched original scripted dialect.
- Rounding covers exact milliseconds, every remainder 1 through 9, half-centisecond ties, zero start, collapse, upper integer bounds, one loss per changed endpoint, and strict refusal.
- Literal braces, literal recognized escape pairs, unmatched markup, arbitrary backslashes, commas, actual newlines, NBSP, Unicode, adjacent blank lines, trailing spaces, and nested emphasis have explicit semantic or fatal checks.
- Both dialect conversions test all nine alignment positions, common style/actor/effect preservation, ASS-only columns, SSA AlphaLevel/TertiaryColour, different outline/shadow colors and alpha, Layer/Marked, comments, unknown records, attachments, malformed preservation-only owners, and safe source capture linkage.
- Constructed renderer checks invalid context, cancellation, source tampering including secondary assets, model ownership mismatch, record/output limits, and complete candidate reparsing before any bytes are returned.

## External primary references

The [maintained libass file-generation guide](https://github.com/libass/libass/wiki/ASS-File-Format-Guide) documents the distinct style/event declarations, matching ScriptType, alignment roles, and recommends Marked=0 for SSA. It identifies itself as guidance rather than a comprehensive authoritative specification. Cueson's ratified narrower grammar remains controlling.

The [libass style parser source](https://github.com/libass/libass/blob/master/libass/ass.c) demonstrates SSA's shared outline/shadow BackColour behavior and AlphaLevel handling. These observed renderer differences motivate conservative atomic loss accounting; Cueson does not render pixels or load fonts.

The [Aegisub override-tag manual](https://aeg-dev.github.io/AegiSite/docs/3.0/ASS_Tags/) documents explicit bold/italic enable/disable overrides. Its syntax does not justify adding an unratified brace-escape behavior to Cueson's shared scanner.
