## Outcome

One reviewed candidate revision has matching software/schema identity, immutable candidate schema, and independently verifiable release assets.

## Context

Release readiness is separate from tag, GitHub Release, and production authorization.

## Scope

Finalize 1.1.0 identity and stable capability declarations, add the immutable release-schema copy, prepare concise release notes and packaging, and run the existing non-publishing release proof against the exact candidate.

## Acceptance criteria

- [ ] Executable, emitted/embedded current schema, canonical identity, candidate schema copy, and planned tag version all equal 1.1.0.
- [ ] The candidate schema is byte-identical across repository, embedding, and all package artifacts; historical release copies remain unchanged.
- [ ] All six target archives, six target-bound SPDX JSON SBOMs, and checksum manifest pass the current release contract.
- [ ] Native package smoke tests and command/version/old-input checks pass on the supported hosted platforms.
- [ ] Concise formatted release notes end with the required full-changelog link and accurately state support scope.
- [ ] No tag, GitHub Release, public schema, or production deployment is published by this preparation outcome.

## Dependencies

Native blockers: [#64](https://github.com/shruggietech/cueson/issues/64). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Run full local/hosted gates and packaged release proof, archive/member/SBOM/checksum/identity checks, immutable hash comparison, and exact-candidate evidence read-back.
