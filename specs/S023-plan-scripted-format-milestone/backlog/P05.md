## Outcome

The unreleased next schema can express the ratified ASS/SSA native model alongside unchanged historical formats.

## Context

Schema-first development is encouraged by the main plan, but schema recognition must remain separate from codec availability.

## Scope

Add strictly named native shapes, semantic invariants, annotations, and examples for the two scripted formats. Extend current capability declarations truthfully and preserve historical document contracts; establish the next development identity under the approved version policy.

## Acceptance criteria

- [ ] [#53](https://github.com/shruggietech/cueson/issues/53) native section, style, event, attachment/reference, and override structures are represented without destructive flattening.
- [ ] Every public field has meaningful machine-readable descriptions and valid examples; provenance and source references resolve.
- [ ] Schema recognition is explicitly provisional until codecs and conformance gates pass; no codec or stable support is implied prematurely.
- [ ] SubRip/WebVTT semantics and accepted historical inputs remain compatible; unknown fields and relationships reject according to the owning version.
- [ ] Software/current schema identity remains in lockstep; no released artifact or production schema is changed.

## Dependencies

Native blockers: [#53](https://github.com/shruggietech/cueson/issues/53), [#54](https://github.com/shruggietech/cueson/issues/54). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Compile metaschema and models; validate positive/negative native examples, recursive annotation coverage, identity relationships, historical fixture regressions, and source/privacy invariants.
