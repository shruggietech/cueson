## Outcome

Every relevant CLI surface recognizes and reports the new formats consistently with the ratified capability contract.

## Context

Encoding/rendering/conversion alone leave discovery and validation gaps unless the shared CLI catalogue and validated-input path are integrated.

## Scope

Extend native and Cue JSON validation, privacy-bounded inspection, help, completion, aliases, and capability reporting. Keep all existing commands/options/streams/error classes compatible.

## Acceptance criteria

- [ ] Validate and inspect agree with encode/render/convert about content selection, schema identity, semantic rules, and codec availability.
- [ ] Inspection reports truthful native capabilities and useful scripted counts without source bytes, runtime paths, or local identity.
- [ ] Help and all four completion definitions expose the approved tokens and targets from one catalogue.
- [ ] Invalid invocation, malformed input, unsupported identity/capability, stdout failures, and overwrite/strict rules retain their documented error classes.
- [ ] The [#54](https://github.com/shruggietech/cueson/issues/54) old-document command matrix and existing CLI fixtures continue to pass.

## Dependencies

Native blockers: [#61](https://github.com/shruggietech/cueson/issues/61). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Run shared-input command conformance, complete CLI matrix, help/completion snapshots, privacy and diagnostic/output failure cases, and native platform CI.
