## Outcome

The approved exact candidate is available as an independently verified official release.

## Context

A green candidate does not authorize protected release transitions; publication needs explicit operator authority.

## Scope

Under specific authorization, publish the exact annotated version tag and official GitHub Release with the approved artifact set; verify public bytes and reconcile release records.

## Acceptance criteria

- [ ] The tag resolves to the reviewed approved revision; software/schema/tag identities and asset checksums agree.
- [ ] The official non-draft release contains the approved six archives, six SPDX SBOMs, and checksum manifest with no missing or unexpected assets.
- [ ] Downloaded public assets independently pass identity, integrity, package smoke, schema-byte, and old-input compatibility checks.
- [ ] Release notes pass github-format and exact body read-back; published evidence records the verified revision and artifact identities.
- [ ] The publication issue closes only after independent verification; the overall milestone/epic remains open until all scoped children, including public hosting, complete.
- [ ] No new release or tag is created without its explicit authorization.

## Dependencies

Native blockers: [#65](https://github.com/shruggietech/cueson/issues/65). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Read back tag and Release state, download and verify every asset and packaged schema, run native smoke evidence, and audit linked issue/Project/release lifecycle state.
