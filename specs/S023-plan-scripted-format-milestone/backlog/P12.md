## Outcome

The new formats satisfy the same bounded parsing, rendering, integrity, and cross-platform proof standards as existing formats.

## Context

Complex overrides, field declarations, attachments, and malformed sections add new ambiguity and allocation surfaces.

## Scope

Close conformance coverage gaps, add meaningful parser/render-cycle fuzz targets and seeds, exercise limits and malformed boundaries, and integrate deterministic verification with the current CI.

## Acceptance criteria

- [ ] Every required [#53](https://github.com/shruggietech/cueson/issues/53)/[#57](https://github.com/shruggietech/cueson/issues/57) matrix row has executed evidence and every accepted fixture restores exactly.
- [ ] Fuzz boundaries cover format detection, both parsers, overrides/field declarations, and model-render-reparse cycles without filesystem writes or unbounded allocation.
- [ ] Complexity limits reject rather than silently truncate structures, diagnostics, or conversion losses.
- [ ] Adversarial model/source mismatches, corrupt envelopes, unsafe names/references, and path leaks are rejected at the owning boundary.
- [ ] Windows/macOS/Linux execution and six pure-Go target builds pass; old formats retain their established corpus outcomes.
- [ ] All required CI, security, and review findings are handled before the slice closes.

## Dependencies

Native blockers: [#62](https://github.com/shruggietech/cueson/issues/62). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Run complete corpus and semantic cycles, focused fuzz budgets and retained regressions, race tests where supported, static/vulnerability/security checks, native CI, and release proof.
