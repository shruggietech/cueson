## Outcome

A provenance-verified corpus provides row-level evidence for both scripted native contracts.

## Context

The existing fixture manifest is the shared inventory authority. ASS/SSA must reuse it rather than introduce a parallel testing dialect.

## Scope

Add authored or appropriately licensed fixtures and expected projections for all [#53](https://github.com/shruggietech/cueson/issues/53) acceptance rows, including encodings, native variants, malformed syntax, unknown sections, overrides, drawings, karaoke, embedded attachments, and references.

## Acceptance criteria

- [ ] Every payload has one manifest entry, redistribution evidence, exact byte count/hash, and intentional encoding/line-ending provenance.
- [ ] Fixtures cover both variants, reordered/extended Format declarations, dialogue commas, duplicate/unknown fields, styles, comments, non-dialogue events, overlap, boundaries, and limits.
- [ ] Normalized expectations separate native retention, common cues, speaker/token observations, and ordered diagnostics.
- [ ] Every accepted fixture has an exact-restoration expectation; no original runtime path or machine identifier leaks into generated model/report expectations.
- [ ] The conformance matrix links each required row to fixture IDs and the applicable ingest/render/conversion assertion; future assertions are not marked passed.

## Dependencies

Native blockers: [#56](https://github.com/shruggietech/cueson/issues/56). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Run fixture inventory, provenance, hash, privacy, encoding, and row-coverage verification; execute the corpus through [#58](https://github.com/shruggietech/cueson/issues/58) and [#59](https://github.com/shruggietech/cueson/issues/59).
