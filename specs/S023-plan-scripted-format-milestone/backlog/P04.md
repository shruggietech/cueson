## Outcome

The new executable accepts and processes the ratified historical v1.0.0 contract through a deterministic local validation path.

## Context

[#54](https://github.com/shruggietech/cueson/issues/54) defines backward compatibility; the present single-schema path needs a bounded extension rather than permissive version guessing.

## Scope

Implement exact identity dispatch and version-aware semantic validation in the existing shared validated-input path. Embed or otherwise package the required immutable historical contract locally. Preserve current output schema discovery and lockstep behavior.

## Acceptance criteria

- [ ] The [#54](https://github.com/shruggietech/cueson/issues/54) command/version matrix passes with historical schema identity and producer information preserved.
- [ ] A valid historical document is accepted by every promised command, and historical invalid documents remain rejected for the correct contract.
- [ ] Current schema emission remains byte-identical to the current canonical artifact, independently of historical input support.
- [ ] Unknown, mismatched, and unsupported identities reject before publication; no network access is required.
- [ ] Immutable v0.0.0 and v1.0.0 schema hashes remain unchanged, and existing command outcomes remain compatible.

## Dependencies

Native blockers: [#54](https://github.com/shruggietech/cueson/issues/54). Coordination across the same implementation slice does not add reciprocal dependencies. Protected release/tag and production transitions require their own explicit operator authority.

## Verification

Run schema and semantic positive/negative fixtures, command-level old-document regressions, source integrity and restoration checks, native platform CI, immutable hash and embedded-byte checks.
