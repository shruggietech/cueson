# Data Model: Prepare v1.1.0 public schema and site

## Current release identity

- `version`: exact semantic version without a leading `v`; for this slice `1.1.0`.
- `tag`: exact Git tag; MUST equal `v` plus `version`.
- `url`: exact official GitHub Release URL for `tag`.
- Relationships: owns the expected tag/version prefix for every primary download and is copied into generated content/deployment metadata.
- Validation: all fields present and exact; no mutable latest URL or branch URL; mismatch with any download fails generation.

## Download record

- `name`: unique user-facing target label.
- `url`: exact GitHub Release asset URL.
- Relationships: belongs to current release identity; filename is one approved archive or checksum manifest.
- Validation: exactly seven unique records; six platform archives plus one checksum manifest; exact version/tag match; no SBOM is promoted as a primary package action.

## Released schema record

- `version`: immutable schema release version.
- `source`: versioned repository authority path.
- `public`: canonical versioned public path.
- `byte_length`: exact expected source/output length.
- `sha256`: lowercase exact digest.
- Relationships: one record per released version; becomes one declared schema route and one artifact file.
- Validation: versions and paths unique; source bytes match length/digest; public path embeds exact version; no `latest` record.

## Documentation record

- `source`: maintained repository document.
- `slug`: stable public route segments.
- `title`, `description`, `order`: public metadata/navigation identity.
- Relationships: deterministic source-to-generated adaptation and one HTML route.
- Validation: source and output paths safe/unique; v1.1.0 release page is ordered before retained older releases.

## Content manifest

- `release`: current release identity.
- `documents`: source/route/source-digest/output-digest entries.
- `schemas`: version/source/public route/length/digest entries.
- `downloads`: exact current release actions.
- `brand_assets`, `direct_files`: retained generated asset identities.
- Validation: stable deterministic JSON; exact complete arrays; generated bytes reproduce the recorded digest.

## Deployment record

- `commit`: exact revision that generated the artifact.
- `release`: current release identity.
- `content_manifest_sha256`: digest of public `content-manifest.json` bytes.
- `routes`: complete ordered route inventory (22 HTML and three schema routes).
- `downloads`: exact seven URL inventory.
- `schemas`: exact three version/path/length/digest identities.
- Relationships: generated from the same content authority and compared byte/logical-field exact with production read-back.
- Validation: no remote self-declared subset may replace local reviewed inventory.

## Production verification observation

- `selected_revision`: operator-selected deployment input.
- `origin_main_revision`: freshly fetched default-branch head.
- `remote_deployment`: fetched deployment record.
- `remote_content_manifest_bytes`: fetched public manifest bytes.
- `route/download/schema_results`: probes driven by the local deployment record.
- State transition: selected only when revisions are equal; accepted only after deployment record equality, manifest digest, all route/download/schema/TLS/redirect checks and Cloudflare preservation checks pass.
- Boundary: observations are post-merge #67 evidence and are not produced as successful live proof by #76.
