# Public site update contract

## Release authority

The maintained content authority MUST contain exactly one current release record for version `1.1.0`, tag `v1.1.0` and `https://github.com/shruggietech/cueson/releases/tag/v1.1.0`. Generated content and deployment metadata MUST derive current release identity from that record.

The primary download inventory MUST contain exactly the six approved archive filenames and `cueson_1.1.0_checksums.txt`, each under the exact `v1.1.0` release-download prefix. Names and URLs MUST be unique. SBOMs remain available on the official release but are not primary package downloads.

## Documentation routes

The artifact MUST declare 22 HTML routes and three schema routes. The generated documentation inventory MUST add `/docs/releases/v1.1.0/` and retain `/docs/releases/v1.0.0/` and `/docs/releases/v0.0.0/`.

Current maintained prose MUST describe v1.1.0 as published and independently verified, stable native SubRip/WebVTT/ASS/SSA support, exact historical v1.0.0 input compatibility, new-output 1.1.0 identity and old-consumer refusal. Historical release records and frozen preparation evidence MUST retain their time-bound statements.

## Artifact metadata

The content manifest and deployment record MUST include the exact current release identity and complete reviewed document, download and schema inventories. Generation MUST be deterministic and a check run MUST reject any drift. Route, download and schema records MUST be unique and must correspond to emitted artifact files or external exact asset URLs.

## Authority boundary

Pull-request generation and verification MUST use no production credentials and perform no production mutation. The official PR closes #76 and references #67. Production deployment and live verification remain #67 work after human merge and separate authority.
