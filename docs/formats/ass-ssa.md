# ASS and SSA future format contract

**Status:** Planned v1.1.0 contract, unimplemented in the released v1.0.0 software and schema

S023 defines the bounded native contract for the next scripted-format milestone. It does not add a codec, change the executable version, admit a schema artifact, or make a stable capability claim. The [constitution](../../.specify/memory/constitution.md), [schema baseline](../schema.md), [compatibility contract](../compatibility.md), and [architecture](../architecture.md) control shared behavior. P02 owns this contract; P05 owns its future schema realization; P06-P08 own corpus, ingest, and rendering evidence. The P identifiers refer to atomic outcomes in the S023 milestone plan, not shipped capabilities.

## References and authority

References were inspected on 2026-09-15. They inform the dialect boundaries; the requirements below are Cueson's acceptance and fidelity policy, not a promise to reproduce a particular pixel renderer.

The source supplies concrete canonical field lists and illustrates declared-field parsing, `Actor`/`Name` compatibility, and centisecond arithmetic.
- R4: [Aegisub 3.4.0 document parser](https://github.com/TypesettingTools/Aegisub/blob/b0fc741099f610ee9486bfaf0186d39f74b8d756/src/ass_parser.cpp), pinned commit `b0fc741099f610ee9486bfaf0186d39f74b8d756`. Its recognized project metadata identifies external-media and automation fields requiring a deliberate privacy boundary. Cueson does not adopt its omission of comments or unknown content.
- R5: [Aegisub 3.4.0 event parser and serializer](https://github.com/TypesettingTools/Aegisub/blob/b0fc741099f610ee9486bfaf0186d39f74b8d756/src/ass_dialogue.cpp), pinned to the same commit. It distinguishes dialogue/comment records, event text, and drawing spans; its source also records disagreement between renderers on unmatched braces. Cueson therefore defines its own deterministic malformed-content treatment.
- R6: [Aegisub Attachment Manager](https://aegisub.org/docs/latest/attachment_manager/), accessed 2026-09-15. Embedded fonts and graphics are retained content, never permission to load, install, rasterize, or execute an asset.

The planned canonical JSON format keys and CLI tokens are `ass` and `ssa`; `.ass` and `.ssa` extensions are detection hints, not authority. Content must declare `ScriptType: v4.00+` for ASS with `[V4+ Styles]`, or `ScriptType: v4.00` for SSA with `[V4 Styles]`. R1 documents these dialect distinctions. v4++, ASS2, older SSA versions, container packet grammars, and libass-specific extension semantics are outside the accepted profile. Unknown extensions inside an otherwise accepted document remain retained native content with diagnostics.

Detection scans bounded decoded content for Script Info, one unambiguous ScriptType value, and a matching style section. An extension mismatch is diagnosed; mixed style dialects, missing or conflicting ScriptType declarations, and unsupported dialects fail the whole encode operation. Identical repeated ScriptType declarations may be retained with a duplicate diagnostic. There is no silent fallback from an ambiguous script to a different codec.

## Encoding, timing, and source authority

The accepted text-decoding profile is valid UTF-8, optionally beginning with a UTF-8 BOM. LF and CRLF source line endings are accepted and observed. Invalid UTF-8, other selected encodings, NUL, and bare CR fail with deterministic diagnostics. SSA's historical style `Encoding` field is preserved as a native charset identifier; it never selects a system codepage or changes the UTF-8 decoding contract. Legacy encoded SSA remains an explicit later expansion, not implicit platform-dependent support.

Source capture uses the existing 64 MiB input ceiling and source-envelope integrity rules. The original primary script bytes, byte length, and SHA-256 are unchanged. Native decoded line views exclude terminators and the leading BOM, while the source envelope retains both exactly. A captured filename is a portable safe basename; a caller path, working directory, user identity, hostname, or discovered asset path is never written into Cue JSON. Exact restoration verifies and reproduces the accepted original asset, independently of all native/common edits.

Accepted event timing is nonnegative `h:mm:ss.cc` with one or more hour digits, exactly two minute/second/fraction digits, minute and second ranges 00-59, and fraction range 00-99. Checked integer arithmetic computes milliseconds as `((h * 60 + mm) * 60 + ss) * 1000 + cc * 10`; overflow or a nonpositive dialogue interval rejects encode. Event starts are inclusive and ends exclusive. Source order, overlap, and decreasing starts remain intact, with decreasing starts diagnosed. This is a deliberately bounded timing profile; Cueson does not copy permissive integer scanning or overflow behavior from R3.

`Timer` must be absent or numerically equal to 100. A syntactically invalid or non-100 Timer fails the whole encode operation with `unsupported_timer`; no apparently usable common timing is fabricated. Duplicate identical Timer declarations are retained and diagnosed; conflicting declarations fail. Non-100 timer semantics are deferred until an explicit contract and tests exist. Rendering edited times not divisible by 10 milliseconds fails with `unrepresentable_centiseconds`, without silent rounding. P09/P10 define any reported conversion quantization policy, but strict conversion must reject that loss.

## Ordered native shape and declared fields

The future schema must realize the following structural ownership. These are required logical shapes for P05, not JSON accepted by the current executable.

| Location | Planned properties and meaning |
|---|---|
| Root `format_data.ass` or `format_data.ssa` | `dialect`, ordered `sections`, ordered `records`, ordered `styles`, ordered `events`, ordered `attachments`; each occurrence has a document-local ID and explicit references. Only the branch matching root `format` exists. |
| Section occurrence | `section_id`, `source_order`, `name`, and optional capture-only `raw_header`; repeated section names remain distinct occurrences. |
| Record occurrence | `record_id`, `source_order`, `section_id`, `kind`, optional capture-only `raw_line`, and applicable ordered `fields` or reference to its style/event/attachment. Blank lines, comments, unknown lines, declarations, and malformed retained records all participate. |
| Field declaration | Declaration record ID, exact ordered field names, and normalized recognized field identity per occurrence; no map deduplication. |
| Field occurrence | `field_name`, `raw_value`, and an optional recognized typed value; unknown names and duplicate occurrences remain ordered. |
| Style occurrence | `style_id`, `record_id`, `declaration_id`, `name`, and ordered native field occurrences. Name lookup refers to a specific style occurrence, never merely a mutable map entry. |
| Event occurrence | `event_id`, `record_id`, `declaration_id`, `event_type`, applicable `cue_id`, ordered native fields, and `text`; retained comments/unsupported events do not pretend to be dialogue cues. |
| Attachment occurrence | `attachment_id`, `header_record_id`, `data_start_record_id`, `data_record_count`, `attachment_type`, and safe `name`; the contiguous range resolves to ordered encoded-data records whose raw lines own the retained content. Any derived decoded length/hash is separately checked and never replaces the original script. |
| Scripted cue `format_data.ass` or `format_data.ssa` | `event_id`, `style_id`, optional capture-only native timestamp lexemes, and explicit native-derived projection provenance. Only the matching native branch exists. Common timing owns editable dialogue timing; the referenced event owns editable native Text and non-time native fields. |

These native structures live under the matching `format_data.ass` or `format_data.ssa` branch, following the existing SubRip/WebVTT ownership pattern. They never flatten into the shared `format_data` object or coexist as mixed native branches. `source_order` is unique and contiguous across section-header and record occurrences, allowing reconstruction of the entire decoded physical-line sequence. Style, event, and attachment arrays use references into this sequence, not a second independent ordering. Each common cue's `source_order` equals the position of its owning dialogue record; it is a reference to that position, not another sequence participant. An empty primary script is invalid. Record references resolve exactly once; duplicate IDs, orphaned occurrences, missing ownership, cycles, and mismatched dialects are semantic errors. Ordered original raw views are capture observations: edits cannot silently transform them into claims about the original source.

Each matching section occurrence begins with no active Format declaration. A valid `Format:` declaration applies only to subsequent matching records in that occurrence, until another declaration appears. Names are recognized by ASCII case-insensitive comparison after removing surrounding ASCII spaces in the declaration view; exact original names and spaces remain retained. `Actor` is an explicitly accepted alias for the event `Name` field, following R3. No other alias is inferred. Reordered declared fields and additional unknown fields are accepted when unambiguous.

For events, `Text` must appear once and last. Split only the first N-1 commas for an N-field declaration; the remaining suffix is the complete Text, including commas, trailing spaces, and empty text. Non-Text event fields and all style fields cannot represent a literal comma. There is no CSV quoting or backslash comma escaping. Every field from the applicable canonical list below is mandatory exactly once, subject to the explicit Name/Actor alias; unknown extra fields may occur before final Text. Duplicate recognized fields, simultaneous Name/Actor aliases, missing mandatory fields, missing active declarations, invalid field counts, and non-final Text make the affected record uninterpretable. A malformed Dialogue record fails whole encode because discarding its semantics would hide a timed unit; a bounded malformed non-dialogue record may be retained with `malformed_native_record` and blocked from rendering.

The canonical native lists in R3 are the serialization defaults for newly constructed records. ASS style fields are `Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, OutlineColour, BackColour, Bold, Italic, Underline, StrikeOut, ScaleX, ScaleY, Spacing, Angle, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, Encoding`. SSA style fields are `Name, Fontname, Fontsize, PrimaryColour, SecondaryColour, TertiaryColour, BackColour, Bold, Italic, BorderStyle, Outline, Shadow, Alignment, MarginL, MarginR, MarginV, AlphaLevel, Encoding`. ASS events use `Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text`; SSA substitutes `Marked` for Layer, with canonical value `Marked=0`.

## Styles, events, text, and derived observations

Every bounded style occurrence remains ordered and retains complete native values. Recognized values expose typed booleans, integers, finite decimals, color components, font-family names, margins, and alignment without rewriting lexical values. ASS colors preserve ABGR-native meaning; SSA TertiaryColour, AlphaLevel, and legacy alignment remain distinct rather than coerced into ASS equivalents. No font is resolved against the local machine. Invalid styles are retained and diagnosed; any Dialogue referencing an invalid, missing, or duplicate-name ambiguous style fails whole encode with `unresolved_style`. Unused duplicate style names may remain with a diagnostic, but block strict rendering.

Dialogue records map one-to-one to common cues, including empty text and drawing-only dialogue. Cue IDs are generated document-local identities, not native line numbers or source paths. Common `payload.raw_text` equals the exact event Text. `payload.lines` is the ordered logical readable-line projection under the hard/soft-break, override, and drawing rules below; `payload.plain_text` joins those lines with LF. Native Text and raw_text retain every original escape and override, independently of this derived projection. Empty text or drawing-only dialogue produces one empty logical line; leading, consecutive, and trailing explicit breaks retain their empty lines. Commentary, blank records, metadata, unsupported event types, styles, and embedded assets remain native document content, without artificial common cues.

Projection recognizes R2's `\N` as a hard line break, `\h` as U+00A0, and `\n` as a line break only with effective wrap mode 2, otherwise a space. Cueson does not simulate automatic wrapping, collision layout, glyph shaping, or video geometry. Effective WrapStyle and `\q` state determine only this explicit soft-break interpretation. Unknown or invalid wrap state producing ambiguous text fails dialogue projection rather than inventing layout.

For example, native Text `first\Nsecond` produces logical lines `["first", "second"]` while raw_text remains `first\Nsecond`. Text `first\nsecond` produces the same two lines with effective wrap mode 2 and `["first second"]` otherwise. Projection scans explicit escapes only in literal text spans, preserving malformed ambiguous content under the rules below rather than treating override parameters or drawing commands as readable line breaks.

An iterative scanner retains Text and separates ordered literal-text, override/comment, and drawing spans with half-open Unicode scalar offsets into Text. Override blocks and tag occurrences preserve lexemes, duplicate tags, parameters, and encounter order. Basic emphasis and reset state (`\b`, `\i`, `\u`, `\s`, `\r`) may supply derived semantic spans; positioning, movement, clipping, transforms, fading, colors, scale, rotations, font selection, and effects remain native semantics with no visual-equivalence claim. Unrecognized tags are retained and diagnosed, never deleted. Unterminated or nested braces are retained verbatim with `malformed_override`; plain-text projection keeps ambiguous text rather than deleting it, and strict rendering/conversion refuses the diagnosed ambiguity. This differs deliberately from renderer-specific recovery noted in R5.

Positive `\p` enters drawing mode and `\p0` leaves it. Drawing spans and drawing commands remain native and are excluded from readable dialogue text, with native-derived provenance explaining that exclusion. Unsupported drawing commands, clipping paths, and baseline offsets remain retained. Invalid or ambiguous drawing-state transitions fail encode because reliable dialogue-vs-drawing projection is unavailable. A drawing-only cue has empty derived plain text while retaining its timed native payload; conversion must report the drawing loss, not silently omit its existence.

Karaoke tags `\k`, `\K`, `\kf`, and `\ko` retain native centisecond durations and variant identity. The selected derived token profile requires nonnegative checked durations, sequential cumulative timing anchored to cue start, and intervals within the cue. `\kt`, negative/overflowing durations, ambiguous nested state, and out-of-cue sums remain retained with `unsupported_karaoke_timing`; they produce no fabricated timed tokens and block strict operations. Native syllable occurrences remain inspectable even when timed tokens cannot be derived. Name/Actor values yield only native speaker observations, with explicit event-field provenance; no speaker inference uses style names, local accounts, or attachment metadata. Text-native cues have no OCR observations unless a later explicitly provenanced operation supplies them.

## Attachments, external metadata, and privacy

Embedded font and graphic declarations and their encoded lines remain ordered inside the captured script. Header names must satisfy the existing portable safe-basename rules; duplicate safe names are retained as distinct occurrences with a diagnostic, not written to a filesystem. The selected attachment profile checks the custom 6-bit encoded alphabet, final-group validity, line bounds, and decoded length without loading a font or image. Malformed bounded encoded content is retained with `malformed_attachment` and blocked from model rendering; whole encode fails if it exceeds a limit. Embedded binary bytes are content, not executable authority. Do not register fonts, decode image pixels, extract attachments, or discover companion assets during these workflows.

R4 identifies `Audio URI`, `Audio File`, `Video File`, `Timecodes File`, `Keyframes File`, `Automation Scripts`, `Last Style Storage`, and authoring settings as external-resource or environment metadata. Nonempty known resource/path fields, path-bearing attachment headers, and explicit machine identity metadata fail whole encode with `unsafe_source_metadata`, including their occurrences in Script Info, Aegisub Project Garbage, or equivalent recognized authoring locations. Empty resource fields may be retained. Relative paths and remote URIs are also rejected in these known slots: they neither become safe basename guesses nor authorize access. Automation templates, Command events, and explicit script execution references are rejected with `unsafe_active_content`, without running them.

This is a deliberate accepted-source restriction rather than silent sanitization. Deleting only parsed metadata would leave prohibited information inside the required original source bytes. A rejected operation therefore publishes no Cue JSON or rendered output, and never modifies the caller's source. Unknown inert authoring records remain retained when practical; privacy checks must inspect recognized path/identity slots in original decoded records and future edited native values before publication. They must not mistake arbitrary dialogue punctuation, a spoken filename, or a font-family name for captured runtime identity. Diagnostics identify the reason and bounded record position, never echo an unsafe path, machine identity, asset bytes, or script body.

## Model edits and deterministic rendering

Restoration always reads integrity-verified source assets, not reconstructed records. Rendering validates the complete future model, native references, privacy rules, and ownership before opening a destination. Recognized records are serialized from owning structured values; `raw_line` is never replayed over edited timing, Text, style fields, or declared-field values. Capture-time timestamp lexemes and raw time-field occurrences remain unchanged observations while common timing supplies canonical rendered Start/End. Regenerating rendered timestamps does not normalize or rewrite those original-source views; semantic validation must not demand their equality to an edited common time. Editing event Text requires updating common raw payload and its deterministic derived text/speakers/tokens consistently; editing only derived plain text is rejected with `inconsistent_projection`. Common timing changes similarly require recomputing derived karaoke token timing. These failures prevent silently stale views from overriding or ignoring user edits.

Non-time native field edits must update both the owning typed value and its lexical occurrence, or omit the optional typed value so the validator derives it from that occurrence. Start/End are the explicit exception: common timing owns edits and captured native time lexemes stay original observations. Multiple competing editable values are invalid. Known records retain their active declaration's accepted field order, including unknown fields; renderer inserts canonical declarations only for newly constructed sections/records that have no source declaration and contain every required field. All style/non-Text fields reject inserted commas, CR/LF, NUL, and unsafe metadata before publication. No serializer replaces commas with semicolons or silently removes newlines, even though R5 illustrates such behaviors in another tool.

Capture-only raw_header, raw_line, and timestamp lexemes are present for ingested occurrences when observed, and omitted for newly constructed occurrences without a captured value. They are never fabricated from canonical output or required to equal later edited values. Constructed recognized sections and records serialize from their structured owners and common timing. Retained uninterpreted records and encoded attachment-data records require their truthful raw_line because no structured content owner can reconstruct them; constructing such a record without an explicit supported content owner fails model validation. P05/P08 must verify new structured section/style/dialogue construction without capture fields, alongside edited captured-record rendering.

The renderer writes UTF-8 without BOM, LF physical lines, normalized prefixes, deterministic canonical recognized scalar formatting, retained ordering, and a final LF. Unknown inert lines and blank/comment records may reuse their retained decoded raw text after safety checks. It never reorders by timestamp, deduplicates styles/events, executes effects, flattens overrides, or fetches attachments. Uninterpretable declarations, malformed retained records/attachments, unresolved ownership, or unsafe ambiguity fail rendering in all modes. Permissive rendering may emit safely interpretable diagnosed unknown/duplicate native content with warnings; strict mode rejects every known conformance ambiguity before publication.

Parse-render-parse equivalence compares dialect, complete item ordering and occurrence identities after position-based remapping, declared unknown field/value order, styles, events, attachments, common timing/text/speakers/tokens, and safety classifications. Canonical whitespace, BOM, line terminators, numeric lexemes, capture-only raw-line observations, and diagnostic line positions may differ; source restoration is tested separately for exact original bytes. A successful textual cycle proves model semantics and retention under this profile, not identical subtitle pixels across renderers.

## Deterministic diagnostics and bounds

P05-P08 must define and test closed diagnostic identifiers, severity, stable encounter ordering, safe positions, and strict/fatal effects. Diagnostics retain no caller path or unsafe source value. Fatal errors and strict losses publish no partial destination, no partial structured stdout, and no source rewrite. Independent diagnostics cannot be lost through first-error shortcuts except after a fatal acquisition/decoding/complexity boundary makes continued examination unsafe.

The future implementation remains subordinate to the unchanged shared limits: 64 MiB native input, 1 GiB Cue JSON input, 65,536 document items, 1,024 repeated values per item, and 8,192 diagnostics or conversion losses. The [model collection limits](../../internal/model/limits.go) remain the owning implementation baseline. Scripted sections plus physical records have a combined 65,536-occurrence ceiling; each style/event/attachment occurrence references those records rather than amplifying that item count. Field, tag, span, speaker, and token arrays never exceed 1,024 occurrences in their owning item. Attachment data uses a checked contiguous record range rather than duplicating all data lines inside one repeated-value array; ranges must stay in the owning section, reference only encoded-data records, and not overlap another attachment's range. A 128-field declaration ceiling and 1,000,000 total field occurrences further constrain amplification.

Additional selected-profile limits are 1 MiB per physical line, nesting depth 32, 1,000,000 total tags/spans per document, 1,024 attachment occurrences, 16 MiB decoded per attachment and 32 MiB decoded attachment content in total, and 64 MiB canonical native output so accepted rendered files remain within the reparse acquisition bound. Attachment encoded data lines are additionally at most 80 ASCII bytes each; the shared physical-record ceiling can reject a bundle before these byte limits are reached. Checked arithmetic and iterative scanning prevent overflow, recursion exhaustion, and superlinear rescanning. Crossing any ceiling fails with `complexity_limit`; no silent truncation, omitted record, replacement source envelope, or success-with-incomplete-diagnostics/losses is allowed. P12 must prove native platform and fuzz boundaries; any limit adjustment requires an explicit contract change with evidence before stable freeze.
